# 다섯 모션의 자연 연결 시도 v1

[기존 전환 점검](ppo_humanoid_transition_audit_v1.md)에서 단순 연결이 실패한 뒤, 걷기와 다음 모션의 **지지 발을 맞추고** 원본 긴 모션의 **진입·이탈 구간**을 활용했다. 모든 결과는 같은 generic humanoid, Isaac Lab, 고정 PPO checkpoint `outputs/ppo_humanoid_five_motion_continue_2500_seed0/model.pt`, seed 0, 첫 프레임 시작의 물리 rollout 1회다. 별도 PPO 학습이나 관절 blend는 하지 않았다. 성공 판정은 clip end와 마지막 자세·추종 오차를 함께 본다.

| 전환 후보 | 경계의 발 위치 차이 최대 | 종료 / 시점 | 종료 몸통 기울기 | 관찰 |
|---|---:|---|---:|---|
| 걷기→좌회전, 4.5–8.0초 진입 포함 | 0.035m | SUCC / 5.43초 | 12.9° | 기존 개선안. 끝 발 위치 오차 약 0.24–0.28m |
| 걷기→우회전, 4.5–8.0초 진입 포함 | 0.056m | FAIL / 3.13초 | 29.1° | 지지 발만 맞춰도 회전 중 이탈 |
| 걷기→우회전, 걷기 한 주기 추가 | 0.056m | FAIL / 3.87초 | 46.5° | 연결 시점 2.39초; 추가 준비 구간도 해결 못 함 |
| 걷기→정지, 오른발 지지 정렬 | 0.069m | FAIL / 2.00초 | 36.2° | 정지 clip 초반에서 이탈 |
| 좌회전→걷기, 원본 이탈 구간에서 연결 | 0.047m | FAIL / 3.97초 | 37.1° | 8.57초 원본 시점에서 연결 후 실패 |
| 우회전→걷기, 원본 이탈 구간에서 연결 | 0.034m | FAIL / 4.33초 | 80.9° | 9.20초 원본 시점에서 연결 후 실패 |
| 좌회전→걷기, 학습 clip 끝 8.0초에서 발 정렬 | 0.061m | FAIL / 3.97초 | 68.5° | 이전 단순 연결과 유사하게 실패 |
| 우회전→걷기, 학습 clip 끝 8.0초에서 발 정렬 | 0.051m | SUCC / 4.03초 | 12.1° | 끝 root/양발 위치 오차 약 0.45/0.50·0.41m로 큼 |

여기서 발 위치 차이는 **reference 양발의 경계 차이**다. 실제 로봇 발의 안정성 지표가 아니다. 좌회전과 우회전은 완전히 대칭적인 물리 정책이 아니며, 한쪽의 연결 시점이 다른 쪽에서도 작동한다고 가정할 수 없다. 별도 단독 평가에서 4.5–8.0초 좌·우회전 clip은 각각 시작 후 약 0.93초와 0.87초에 실패했다. 반면 기존 5–8초 우회전 clip은 단독으로 끝까지 갔다. 따라서 회전 직전 0.5초가 tracker에 익숙하지 않은 상태일 수 있다. 좌회전 연결 개선은 선행 걷기가 이 상태로 진입하는 데 도움을 준 한 사례이며, 일반화 증거는 아니다.

회전→걷기 원본 이탈 시도는 `scripts/build_turn_exit_walk_probe.py`가 원본 긴 모션에서 root yaw 속도가 작고 발이 거의 정지한 시점을 찾은 뒤 같은 지지 발의 걷기 phase를 붙인 것이다. 첫 생성 v1은 원본의 월드 방향을 그대로 사용해 **학습 clip과 출발 heading이 달랐다**. v1의 물리 결과는 비교에서 제외했다. v2에서는 원본을 학습된 5–8초 clip처럼 +X 방향과 root XY=0으로 맞췄고, 첫 100프레임이 기존 clip과 완전히 같음을 확인했다. 그래도 연결 뒤 실패했다. 8초에 고정한 후보는 학습 구간을 넘어가지 않지만 좌회전은 실패하고 우회전은 끝 오차가 남았다.

원자료: 각 후보의 `.pkl` 및 생성 조건 `.json`은 `data/reference_motions/`, 평가 설정은 `configs/envs/`, 실제 물리 시계열과 요약은 `outputs/transition_diagnostics/`의 `walk_turn_right_leadin*`, `walk_stop_contact_seed0`, `turn_*_walk_exit_v2_seed0`, `turn_*_walk_at8_seed0`에 있다. 기존 좌회전 원자료는 `walk_turn_left_leadin_seed0`이다. `scripts/build_contact_aligned_turn_probe.py`는 30Hz 정지 clip을 120Hz로 resample할 수 있고 걷기 주기 수를 바꿀 수 있다.

**판정:** 현재 checkpoint와 단순한 rigid 연결만으로는 모든 전환을 자연스럽게 실행할 수 없다. 다음 관문은 실패 전환의 연속 reference를 물리적으로 만들고(접촉과 속도까지 확인), 그 reference를 포함해 tracker를 적응시킨 후 동일 조건으로 재평가하는 것이다. 또는 실제 tracker rollout으로 목표 조건 전환 데이터가 충분히 생기는지 먼저 확인해야 한다. Diffusion을 학습하면 경계가 자동 복구된다고 가정하지 않는다. 정지 유지(stand hold)도 별도 평가가 필요하다.
